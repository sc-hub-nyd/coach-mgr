# CoachMgr デザインシステム視覚回帰・操作検証プロトコル

**対象：DS-R5 / CoachMgr v1.30.85以降**

## 1. 目的

構造テストだけでは検出しにくい、長い日本語名、複数操作、状態混在、端末幅、テーマ、PWA更新時の崩れを、同じ条件で継続的に確認する。

テスト正本は[`../tests/fixtures/design-system-high-density-fixture.json`](../tests/fixtures/design-system-high-density-fixture.json)である。実データを上書きせず、このフィクスチャの条件を確認シナリオとして使う。

## 2. 固定シナリオ

| 領域 | シード条件 | 確認すること |
|---|---|---|
| 選手・参加者 | 12名、長い日本語名、未回答、注意状態 | 氏名・出欠・数値・操作が重ならず、値列が読める。 |
| 予定・試合 | 長いタイトル、長い場所名、主要操作5個 | カードヘッダーと操作群が衝突せず、モバイルでは操作が押せる。 |
| 状態UI | success / warning / danger / info / pending / empty / loading / disabled | 色だけでなく、ラベル、アイコン、状態説明、フォーカスで意味を判別できる。 |
| 作図 | 移動、パス、ドリブル、コーン、ラダー | 選択前にラベルを読め、選択後は`aria-pressed`・可視状態・Canvas表現が一致する。 |
| PWA更新 | waiting、更新する、再読込、オフライン再起動 | CSS、JavaScript、Tablerサブセットが同じキャッシュ世代で表示される。 |

## 3. ビューポートとテーマ

| 幅 | 代表端末・用途 | 必須テーマ |
|---:|---|---|
| 320px | 小型スマートフォン | light / dark |
| 390px | 一般的なスマートフォン | light / dark |
| 768px | タブレット縦向き | light / dark |
| 1024px | タブレット横向き・小型PC | light / dark |
| 1280px | デスクトップ | light / dark |

横向きスマートフォンでは、サイドナビゲーション、戻るドック、作図ツールドックのスクロール・safe area・タップ領域を追加確認する。

## 5. リリース前の手順

1. 高密度シードの条件を使い、ダッシュボード、試合詳細、練習編集、設定、作図を確認する。
2. 各画面を5幅×light/darkで確認し、横溢れ、重なり、切り詰め、固定ナビの被り、44px未満の主要操作を確認する。
3. キーボードで主要操作へ移動し、可視フォーカス、ダイアログ名、通知の読み上げ、選択状態を確認する。
4. PWAで更新通知を適用し、再読み込み後のバージョン、Tablerアイコン、オフライン起動を確認する。
5. 自動テスト、レスポンシブ検証、`git diff --check`を通してから公開する。

## 6. 失敗時の扱い

横溢れや操作被りは、画面固有の一時的な余白で隠さない。原因をトークン、レイアウトプリミティブ、共通コンポーネント、画面固有データ表現へ分類し、最も再利用可能な層で修正する。例外が必要な場合は、対象幅・対象状態・削除条件を設計負債台帳へ記録する。
