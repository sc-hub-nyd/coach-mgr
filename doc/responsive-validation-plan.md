# CoachMgr v1.17.0 レスポンシブ検証計画

## ビューポート

| 区分 | 幅 × 高さ | 主な確認目的 |
|---|---:|---|
| 小型スマートフォン | 320 × 844 | 最小幅での横溢れ、固定操作、文字・ボタンの切れを確認する。 |
| 標準スマートフォン | 390 × 844 | 片手操作時のField Companion、カード・フォーム・ナビゲーションの折返しを確認する。 |
| タブレット | 768 × 1024 | 二列カード、設定項目、振り返り分析の中間幅レイアウトを確認する。 |
| 小型デスクトップ | 1024 × 768 | サイドナビゲーションと内容幅、複数列グリッド、ツールバーを確認する。 |
| デスクトップ | 1440 × 900 | 最大可読幅、余白、広いグリッドの情報密度を確認する。 |

## 対象画面と合格条件

| 画面 | 主要判定 |
|---|---|
| ダッシュボード | カードが画面外へはみ出さず、二列領域はモバイルで一列へ折り返す。 |
| 設定 | 長い設定行と入力欄が縮小・折返し、操作ボタンを押せる幅で維持する。 |
| 振り返り | 期間フィルター、比較カード、意思決定カードが幅に応じて再配置される。 |
| 試合詳細 | 基本情報フォームとピリオド一覧が一列化し、横スクロールを発生させない。 |
| Field Companion | 時計、スコア、試合前チェック、操作帯、名簿、試合ログが320px以上で読め、主操作が画面内に残る。 |

合格条件は、`document.documentElement.scrollWidth`がビューポート幅を超えないこと、主要な操作要素が可視であること、Grid/Flexの折返しが意図どおりに起こること、文字およびタップ対象が重ならないことである。意図した横スクロール領域（試合ログ等）が存在する場合は、対象要素内に限定されていることを確認する。
