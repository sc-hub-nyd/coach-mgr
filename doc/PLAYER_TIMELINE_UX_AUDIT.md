# 選手タイムライン UX 監査

## 対象と前提

対象はv1.31.45の選手詳細にある「成長の年表」と「記録を探す」である。年表は学年、月、記録詳細の順にドリルダウンし、検索結果から該当地点を開く。評価では、単発の画面内操作、移動後の文脈回復、スマホ片手操作、保護者の振り返り、コーチの記録探索、キーボード操作を対象とする。

## 現状の良い点

| 観点 | 現状の強み | 維持すべき理由 |
|---|---|---|
| 情報階層 | 学年、月、記録詳細の順で開くため、長い履歴を一度に見せない。 | 初見の保護者にも成長の順序を理解しやすい。 |
| 検索 | サイドバーではなく画面内モードを使い、選手詳細の文脈を失わない。 | モバイルで重なり・閉じ忘れ・二重スクロールを避けられる。 |
| 検索復帰 | 結果を選ぶと該当する学年、月、記録詳細を開き、対象へスクロールする。 | 検索結果が行き止まりにならない。 |
| アクセシビリティ | 開閉はbutton、aria-expanded、aria-controlsで提供している。 | タップ、キーボード、読み上げで同じ情報構造を扱える。 |

## 優先度付きの改善案

| 優先度 | 改善案 | 体験上の狙い | 実装の要点 |
|---|---|---|---|
| P0 | **現在地のパンくずと経路記憶** | 「どの学年・月・記録を開いているか」をスクロール中も失わせない。 | 開いている学年・月・記録を選手ID単位のUI状態として保持し、年表上部またはスクロール後の小さな固定行に「6年生 › 8月 › 守備の寄せ」を表示する。新しい選手詳細描画や戻る操作後も同じ経路へ戻す。 |
| P0 | **検索から戻った後の到達フィードバック** | 検索結果を選んだ後に、年表のどこへ移動したのかを一目で理解させる。 | 対象の記録を短時間だけ状態トークンで強調し、「5年生 / 7月の記録を表示中」のライブメッセージと「検索結果へ戻る」操作を出す。動きを減らす設定では即時状態だけを表示する。 |
| P1 | **月間サマリーの先読み** | 月を開く前に、そこに何があるかを判断させる。 | 月フラッグの横に、ノート・観察・試合・練習の件数を小さなアイコンと数で表示する。開いた月には「今月のひとこま」と最新の次の一歩を一行で置く。 |
| P1 | **前後の月へ連続移動** | 1か月ずつ振り返る際の開閉回数と移動量を減らす。 | 開いた月の詳細下部に「前の記録月」「次の記録月」を置く。空月は飛ばし、年をまたぐ場合は学年も自然に開く。 |
| P1 | **検索の発見性と条件の可視化** | 「記録を探す」が単なるタブではなく、目的達成の入口だと伝える。 | 年表上部に検索トリガーを置き、検索画面では検索語、種別、結果件数を常時表示する。入力済みの条件には明確なクリア操作を加える。 |
| P2 | **役割別の初期ビュー** | 保護者の「振り返る」とコーチの「探して記録する」を混同させない。 | 保護者は「今月のひとこま」と更新順の足あとを優先し、コーチは前回の検索条件、メモ追加、未記録月への入口を優先する。データと権限は変えず、初期フォーカスだけを分ける。 |
| P2 | **学年の全体像ビュー** | 年表を開く前に、その学年の密度と節目を把握させる。 | 学年見出しに「試合、練習、メモ」の件数と代表テーマを表示し、全月展開ではなく学年の足あとを小さく俯瞰できるようにする。 |

## 推奨する実装順

最初にP0の現在地・経路記憶と検索復帰フィードバックを実装する。これにより、現在の情報構造を変えずに「どこを見ているか」「どう戻るか」の不安を減らせる。次にP1の月間サマリー、前後月移動、検索条件表示を追加し、探索速度を上げる。P2の役割別ビューと学年俯瞰は、年度横断の選手ID監査が済んだ後に拡張する。

## 守るべき境界

年表をカードの大量表示や無制限の全月展開へ戻さない。検索は重なるサイドバーやモーダルではなく、現在の画面内モードを維持する。装飾的な3D、複雑な常時アニメーション、色だけに依存した現在地表示は採用しない。すべての新操作はTablerアイコン、標準button、aria属性、セマンティックトークン、縮退モーションに適合させる。
