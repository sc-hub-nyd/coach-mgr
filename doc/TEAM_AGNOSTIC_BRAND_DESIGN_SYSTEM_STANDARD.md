# 既定チームブランド・デザインシステム標準

**現行基準：CoachMgr v1.30.85**
**対象：CoachMgrのアプリシェル、ナビゲーション、設定画面、共通コンポーネント、既定チーム SVG、Tabler Icons、Canvas作図、PWA**

## 1. 目的

CoachMgrは、未設定チームでも主操作・選択状態・フォーカスを明確に区別できる赤系`#EF3340`を、**既定ブランド基準**として採用する。ただし、CoachMgrは複数チーム・複数年度の運用を前提とするため、赤をすべての画面へ固定するのではなく、利用者が変更可能な種色を安全に役割色へ変換する設計を維持する。

> **原則：ブランド基準色は既定の出発点であり、UI部品が直接参照する完成色ではない。**

## 2. カラー階層

| 層 | 値または識別子 | 責務 | 利用規則 |
|---|---|---|---|
| ブランド既定種色 | `#EF3340` | 新規・未設定チームの一貫した初期表示を支える赤系の出発点 | `teamInfo.theme.seed`の既定値だけに使う。部品から直接参照しない。 |
| チーム種色 | 利用者が選択した任意のHEX | チーム固有のブランド表現 | チーム共有データとして保存する。既存チームの保存値を上書きしない。 |
| 生成プリミティブ | `--theme-primary`、`--theme-canvas`など | 種色とlight/darkから作る内部値 | `color-theme-service.js`のみが生成し、コンポーネントは直接参照しない。 |
| セマンティックトークン | `--color-action`、`--color-text-on-action`など | UIに公開する意味ごとの色役割 | CSS部品はこの層だけを参照する。 |
| 状態ロール | success / warning / danger / info | 業務状態・破壊的操作・注意 | チーム種色から独立する。ブランド赤とdangerを同義にしない。 |

## 3. 赤系既定パレットの運用

`#EF3340`は、操作面・文字・背景・境界の全てに同じまま使わない。`color-theme-service.js`がlight/darkごとに主操作、前景、やわらかい選択面、ニュートラル背景、境界、フォーカスを算出する。動的テーマ適用前だけは、`base.css`の赤系フォールバックを用いる。

| 役割 | 既定フォールバック | 意図 |
|---|---:|---|
| ブランド種色 | `#EF3340` | 既定チーム向けの初期選択値。 |
| 主操作 | `#C72C38` | 白文字と十分な対比を保つ、濃い赤系の操作面。 |
| 主操作hover | `#A92330` | 操作状態を示す、より深い赤。 |
| 控えめなブランド面 | `#FDE8EB` | 選択行、情報の強調、軽いブランド表現。 |
| キャンバス | `#FAF6F6` | 長時間の業務利用でも刺激を抑える、ごく薄い赤白。 |
| 境界 | `#B9A5A8` | カード・入力・区切りを背景から識別する。 |
| フォーカス | `#C72C38` | キーボード操作で可視な焦点を示す。 |

## 4. 任意チームカラーの変更規約

チームカラーは設定画面からいつでも変更できる。入力されたHEXは正規化され、`teamInfo.theme.seed`へ保存される。色相の選択は制限しない。黒、白、グレー、黄、蛍光色、緑、青、紫、赤のいずれも受け付け、主操作と文字、境界と背景の組合せを生成器が補正する。

| データまたは表示 | 責務 | 同期範囲 |
|---|---|---|
| `teamInfo.theme.seed` | チームの種色 | チーム共有・同期対象 |
| `coachMgrUiPreferences.colorMode` | light / dark | 端末ローカル |
| `--theme-*` | 生成済みプリミティブ | 永続化しない |
| `--color-*` | コンポーネント向けの意味トークン | 永続化しない |

既存チームの`teamInfo.color`または`teamInfo.theme.seed`が存在する場合、既定赤への自動上書きは行わない。赤を使いたい既存チームは、設定画面から`#EF3340`を選択できる。

## 5. コンポーネントとアイコンの契約

ブランド表示には`--color-brand`、淡いブランド面には`--color-brand-surface`、濃いブランド面上の文字・アイコンには`--color-text-on-brand`を使う。主操作には`--color-action`または`--color-surface-selected`を使う。本文、補助説明、境界、状態色へ具体的な赤のHEXを埋め込まない。主操作に載る文字とアイコンは`--color-text-on-action`を、通常面では`--color-text`または`--color-text-muted`を使う。

アイコンは、業務操作・試合記録・サッカー補助語彙をローカルTabler Icons 3.46.0（`.ti`）へ統一する。順位など非操作的な補助には絵文字を使用でき、選手位置・線種・図形そのものが意味を持つ戦術表現はCanvas作図で扱う。TablerはローカルCSS・WOFF2としてPWAのprecacheへ登録し、外部アイコンCDNと別のカスタムSVG資産には依存しない。

Tabler Iconsは`currentColor`を継承する。アイコンはラベルを補助し、単独で使う操作には日本語の`aria-label`を設定する。状態は色・アイコンだけで伝えず、テキストか数値も併記する。

### 作図ツールの意味契約

作図では、ツールのアイコン、常時表示する日本語ラベル、`aria-label`、`title`、`aria-pressed`、Canvas上の線種またはオブジェクト形状を同じ意味へそろえる。移動は`ti-route`と実線矢印、パスは`ti-arrow-right-dashed`と点線矢印、ドリブルは`ti-arrow-zig-zag`とジグザグ矢印、コーンは`ti-cone`、ラダーは`ti-ladder`を第一候補とする。右矢印、三点リーダー、心電図、上向き三角、メニュー記号をそれぞれの代替として再導入しない。

作図ツールドックは、選択前にも日本語ラベルを表示し、デスクトップ68px・モバイル64pxの幅を確保する。選択状態は背景色だけで示さず、可視ラベル、アイコン、`aria-pressed`、キーボードの`focus-visible`を同期する。詳細な台帳と変更レビュー規約は[`ICON_SYSTEM.md`](./ICON_SYSTEM.md)を正本とする。

## 6. タイポグラフィとの統合

既定チームの赤系ブランドは、見出しを装飾書体へ置き換えるのではなく、Noto Sans JPとInterによる明瞭で高密度な情報表示で支える。本文・日本語UIは`--font-ui`、見出しは`--font-heading`、スコアや時刻は`--font-numeric`を使う。ブランド色、アイコン、文字はそれぞれの意味トークンを通じて合成し、色だけで重要度を示さない。詳細は[`TYPOGRAPHY_SYSTEM.md`](./TYPOGRAPHY_SYSTEM.md)を正本とする。

## 7. アクセシビリティと検証ゲート

高コントラストモードを設けない代わりに、通常のlight/darkテーマを出荷基準として検証する。

| 検証ペア | 最低基準 | CoachMgrの実装目標 | 検証箇所 |
|---|---:|---:|---|
| 本文 × canvas / surface | 4.5:1 | 5:1 | P34動的テーマテスト |
| 主操作文字・アイコン × action | 4.5:1 | 5:1 | P34動的テーマテスト |
| 境界・フォーカス × 隣接surface | 3:1 | 3.5:1 | P34動的テーマテスト |
| 状態文字 × 状態surface | 4.5:1 | 4.5:1 | P34動的テーマテスト |
| トークン・アイコン契約 | — | 破壊的変更なし | P33 CSSアーキテクチャテスト |
| Tablerローカル配信・未定義クラス | — | Font Awesome再導入なし、全利用クラス定義済み | P42 Tabler移行テスト |
| 作図アイコンの意味・ARIA・幅 | — | 台帳どおりの形、常時ラベル、状態同期 | P43 作図アイコン識別性テスト |
| 状態部品・通知・確認 | 4.5:1 | 状態トークン、live region、dialog名称、inline styleなし | P45 状態部品テスト |
| 部品状態・高密度行 | — | focus・disabled・loading・invalid・12名データが定義済み | P46 部品状態テスト |
| 高密度・PWA更新シナリオ | — | 5ビューポート、更新通知、サブセットprecache | P47 品質シナリオテスト |
| 開発・リリース統制 | — | PRテンプレート、変更履歴、再生成手順が存在する | P48 リリース統制テスト |
| 主要画面の表示幅 | — | 横方向の違反0件 | 5ビューポート × 5画面のレスポンシブ検証 |

動的テーマを変更した場合、`#EF3340`を含む代表種色群のlight/darkテスト、P33、P42、P43、P45〜P48、レスポンシブ検証を全て通過しなければ公開しない。作図ツールを変更した場合は、P40作図回帰テストも必須とする。Tablerクラスを変更した場合は、サブセットCSS・WOFF2・マニフェストを再生成し、P42を通す。

## 8. 実装上の禁止事項

- コンポーネントやHTMLへ`#EF3340`、`#C72C38`などの具体色を直接書かない。
- `--color-text-on-action`を白へ固定しない。任意の明るい種色で読めなくなるためである。
- ブランド赤をdangerロールの代替にしない。
- Tablerアイコンへ直接指定色を追加しない。
- 既存チームの保存済み種色を、既定赤へ無断で移行しない。
- 作図ツールをアイコン単独、色単独、ホバー説明単独のいずれかだけで意味付けしない。
- Tablerに意味の一致する競技固有アイコンがない場合に、曖昧な汎用アイコンで代用しない。必要なアイコンをTablerサブセットへ追加する前に、意味・ラベル・ARIA・作図表現の整合を台帳化する。
- 例外のために`!important`を追加しない。
