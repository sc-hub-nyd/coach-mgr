# CoachMgr サーフェス・デザインシステム

**文書版：2.5 — Neumorphism 2.0 × Liquid UI / Frosted Glass / Kinetic Typography（Neumorphism 2.5: Tactile Silicone Keys & Inset Screens）**

## 1. 目的

CoachMgrのサーフェス表現は、**ニューモーフィズム2.5の触感（シリコンキー調の弾力と多層シャドウ・微細ベベル）**、**Liquid UIの穏やかなブランド層**、および**Frosted Glassの文脈レイヤー**を役割別に組み合わせます。目的は装飾の追加ではなく、操作できる面、情報を読む面、画面に重なる文脈レイヤーを瞬時に区別できるようにすることです。

既定チームの赤系を既定としつつ任意のチームカラーに追従し、ライト／ダークの二つの表示モード、高密度なチーム運営画面、試合中の迅速な記録操作を損なわないことを必須条件とします。

## 2. 役割分担

| 表現 | 役割 | 適用対象 | 適用しない対象 |
| --- | --- | --- | --- |
| **Neumorphism 2.5 (Silicone & Inset)** | 触れられる面・押下状態・情報単位に物理的な弾力・触感（シリコンキー感）とリアルな奥行きを与える。 | カード、一覧項目、フィルターバー、ボタン全般、選択面、入力欄（インセット）。 | 危険操作、主操作の過度な影装飾、読み取り専用の長文領域。 |
| **Liquid UI** | チームカラー由来の淡い色層で、ホーム・計画・次アクションなどの文脈を示す。 | ダッシュボードの文脈カード、モーダル、アプリ背景。 | データ表、タイムライン、エラーや警告の意味付け。 |
| **Frosted Glass** | 現在地・画面遷移・一時的な操作文脈を明確に分離する。 | 上部バー、サイドバー、モバイルナビゲーション、モーダル、ボトムシート。 | 主な読書面、一覧セル、試合中の得点・失点・交代操作。 |

> **基準**：ガラスは「背景が変化しても読める強い半透明面」、ニューモーフィズムは「影だけで意味を持たせない触感」、Liquid UIは「意味色を置き換えない淡い文脈色」として扱います。

## 3. 基本原則

| 原則 | 規約 |
| --- | --- |
| 意味優先 | 色、ラベル、アイコン、境界、状態テキストを残す。影・透過・ぼかしだけで操作可否や重要度を表現しない。 |
| レイヤー優先 | ガラスは固定ナビゲーションとオーバーレイに限定し、通常の情報面はニューモーフィズムまたは不透明面を使用する。 |
| 可読性優先 | 文字の背景が不確定になる箇所では`--glass-surface-strong`を使い、境界とフォーカスリングを必ず残す。 |
| 触感優先（CALC/RATE参照） | ボタンはシリコンキーのような微小グラデーションと多層シャドウ・微細ベベル、押下時は弾力あるインセットと変形（スプリングイージング）を付与する。 |
| ボーダーレス表現 | ニューモーフィズム本来の立体感を際立たせるため、カード・ボタン・入力欄・フィルターバー等の枠線（border）を極力排除し、多層の光と影のグラデーションのみでサーフェスを表現する。 |
| インセット凹面 | 入力欄や数値表示領域は液晶・ディスプレイのように上品に彫り込まれたインセットシャドウを使用する。 |
| 高密度UI | 一覧・表・ログ・試合中操作は過大なぼかし・影・余白を避け、情報量と誤操作防止を優先する。 |
| 性能配慮 | `backdrop-filter`は固定ナビゲーション・モーダルなど少数の大きな文脈面に限定する。 |

## 4. トークン

### 4.1 ニューモーフィズムと形状

| トークン | 用途 |
| --- | --- |
| `--neo-highlight` / `--neo-highlight-crisp` | 光源側のハイライトおよび上部エッジの微細な光の反射ライン（ベベル）。 |
| `--neo-shadow` / `--neo-shadow-soft` / `--neo-shadow-ambient` | 近接エッジ影、拡散アンビエント影、大気影の多層シャドウ構成。 |
| `--neo-surface` / `--neo-surface-gradient` | 浮面・ボタンの基準サーフェス。微細な175deg線形グラデーションで物理的な丸みを表現。 |
| `--shadow-neo-raised` | カード、ボタン、フィルターバーの多層浮面シャドウ。 |
| `--shadow-neo-raised-hover` | 操作可能な浮面のホバー状態（ふわりとした浮遊感）。 |
| `--shadow-neo-pressed` | 検索入力、入力欄、メトリクス、押下状態に使うリアルなインセット凹面。 |
| `--ease-spring` | シリコンキーの心地よい反発・沈み込みを再現するスプリングイージング。 |
| `--surface-inset-*` | カード・空状態・フィルターバーで、文字が角へ近づかない距離を保証する。 |
| `--control-inset-*` / `--control-radius` | 文字を含むボタン・入力欄の共通内側余白と角丸。 |
| `--icon-control-size` | アイコン専用の円形ボタンにだけ使う操作面サイズ。 |

### 4.2 Liquid UIとフロストガラス

| トークン | 用途 |
| --- | --- |
| `--glass-surface` | 通常の半透明レイヤー。文脈面に使用する。 |
| `--glass-surface-strong` | 文字を読む固定ナビゲーション・モーダルに使う強いガラス面。 |
| `--glass-border` | ガラス面を背景から分離する境界線。 |
| `--glass-shadow` | 固定・浮遊するガラス面のレイヤー影。 |
| `--glass-blur` | ガラス面に限定して使うぼかしと彩度。 |
| `--liquid-veil` | チームカラーと補色から合成する淡い文脈グラデーション。 |
| `--liquid-sheen` | 必要時のみ使う控えめな光沢層。本文や操作ラベルの背面には使わない。 |

> 固定の白・黒影、固定の半透明白、固定のブランドHEXを画面固有CSSへ直接記述しません。すべて`tokens.css`のセマンティックトークンを介して表現します。

## 5. コンポーネント規約

| 部品・画面 | 規約 |
| --- | --- |
| `c-card`、`c-practice-card`、`c-data-list__item` | ニューモーフィズムの浮面。通常の読み取り・情報単位として使う。 |
| `c-filter-bar`、`c-choice-field`、`btn-secondary` | 浮面を使い、検索欄や押下状態は凹面にする。 |
| `c-liquid-panel` | 文脈を優先するダッシュボードカードにだけ付与する。濃い色・意味色・データ表には付与しない。 |
| `c-glass-surface` | 一時的な文脈面・補助レイヤーに使用する。本文を持つ場合は`c-glass-surface--strong`を選ぶ。 |
| 上部バー・サイドバー・モバイルナビ | `--glass-surface-strong`と`--glass-blur`を使用する固定ナビゲーション層。 |
| モーダル・ボトムシート | 強いガラス面と淡いLiquid UI層を組み合わせる。本文とフォームは十分な不透明度・境界・フォーカスを維持する。 |
| Field Companion | 得点、失点、交代、警告は意味色と明確なボタン階層を優先し、ガラス表現を適用しない。 |

## 6. 形状と文字開始位置

文字を含むボタン・入力欄は、すべて`--control-radius`による角丸矩形と`--control-inset-*`による共通内側余白を使用します。円形は、文字を持たない`btn-icon`のみに限定します。カード、空状態、フィルターバーなどの面は、`--surface-inset-*`を使用して、先頭文字が角や境界へ近づかない距離を確保します。

| 部品 | 形状 | 内側余白 |
| --- | --- | --- |
| 文字を含むボタン | 角丸矩形 | `--control-inset-*` |
| アイコン専用ボタン | 円形 | `--icon-control-size`、余白なし |
| 通常のカード・空状態 | `--radius-lg`または`--radius-md` | `--surface-inset-*` |
| 高密度のカード・フィルターバー | `--radius-md` | `--surface-inset-compact-*` |

## 7. 禁止事項

- 影、ぼかし、透過だけでクリック可能・選択済み・エラーを表現しない。
- 主な本文、長文、表、試合ログの背面に弱い透明ガラスを使わない。
- `backdrop-filter`を一覧セルや多数の繰り返し要素へ適用しない。
- 固定色の`box-shadow`、固定色のガラス背景、固定ブランドHEXを新規に直接記述しない。
- フォーカスリングを影・ぼかし・ホバー表現に置き換えない。
- 試合中の得点、失点、交代、警告など、誤操作の影響が大きい主操作を装飾優先で弱めない。

## 8. 検証ゲート

統合サーフェスに関する変更は、次の全てを通過してから公開します。

1. P33 CSSアーキテクチャ契約：ニューモーフィズム、Liquid UI、ガラス、共通インセットのトークンと部品を確認する。
2. P34 動的テーマ検証：15種色×ライト／ダークで既存の文字・境界・主操作のコントラストを確認する。
3. P35 DOM契約：Liquid UIを付与した文脈カードと既存の操作IDを確認する。
4. レスポンシブ検証：5画面×5ビューポートで横溢れ、操作不可視、固定ナビゲーションの重なりを確認する。

## 9. Kinetic Typography（テキストモーション）

Colorion Text Effectsの純CSS・動作軽減対応という設計方向を参考に、CoachMgrでは**文字自体を情報として常時読める状態に保ったまま、背景グラデーションと短い導入モーションで文脈を強調する**。アニメーションは機能完了・操作可否・状態の唯一の表現には使わない。

| 表現 | 役割 | 許可する場所 | 禁止する場所 |
| --- | --- | --- | --- |
| `c-text-effect--liquid` | チームカラー由来の穏やかな流体グラデーションで、画面の目的を印象づける。 | ダッシュボードの導入見出し、次回練習・保護者導線、空状態の短い主見出し。 | 入力ラベル、表・ログ、数値、エラー・警告、試合中の主操作。 |
| `c-kinetic-kicker--reveal` | 小さなキッカーを一度だけ短く出現させ、視線の入口を作る。 | 初回表示のホーム、モーダルの補助ラベル。 | 繰返し行、ナビゲーション、キーボード操作の即時フィードバック。 |
| `c-liquid-panel--immersive` | Liquid veil・光沢・浮面を重ね、ホームの次アクションを主役にする。 | ダッシュボードの低頻度な起点カード。 | 試合中操作、タイムライン、データ表、破壊操作。 |
| `c-glass-surface--spotlight` | 読める強いガラス面と柔らかな光を用い、初期導線などの一時的文脈を浮かび上がらせる。 | 初回セットアップ、オンボーディング、モーダル。 | 主読書面、リストセル、試合ログ。 |

モーションは`transform`、`opacity`、背景位置に限定する。ボタンや一覧の高頻度操作は200ms以下、キッカーの導入は420ms以下、Liquid文字の背景移動は3.6秒以上の穏やかな周期とする。`prefers-reduced-motion`または`data-reduce-motion="true"`では、すべてのテキストを静的なセマンティック前景色で表示する。

## 10. 今後の拡張

新しい画面は、まず標準`c-*`部品へサーフェス表現を実装し、画面固有CSSへ複製しません。特殊な作図・試合中UIは、操作安全性、コントラスト、描画性能を個別に検証した後に限定導入します。
