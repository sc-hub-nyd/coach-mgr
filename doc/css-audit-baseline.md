# CSS・レイアウト監査ベースライン

| 指標 | 現状 | 標準化での対応 |
|---|---:|---|
| CSSファイル | 6ファイル | 基盤・レイアウト・部品・画面の責務を明文化し、読み込み順を固定する。 |
| CSS総行数 | 8,931行 | 既存機能を保ったまま、重複した宣言をトークンと部品クラスへ集約する。 |
| `style` 属性 | 539件 | まず反復的なレイアウト指定を標準クラスへ移行し、新規のインライン指定を禁止する。 |
| `!important` | 345件 | カスケード層と低特異性の部品クラスを導入し、例外以外を段階的に削減する。 |
| IDセレクタ | 402件 | JSフックとしてのIDは維持し、見た目はクラスを原則とする。 |
| `u-ext-*` 抽出クラス | 201件 | 意味のない連番を、役割が分かるレイアウト・部品・状態クラスへ置き換える。 |

## 参照方針

指定記事の「一貫した整理、セクション化、外部スタイルシート、DRY、命名規約、アクセシビリティ、`!important`の抑制、Flexbox」の考え方を適用する。CoachMgrはビルド工程を持たない静的PWAのため、導入コストの高いCSSフレームワークやプリプロセッサを追加せず、明示した読み込み順による論理レイヤー、カスタムプロパティ、再利用クラスで実現する。

## 外部参照

指定記事「[CSSのベストプラクティス14選（初心者向け）](https://kinsta.com/jp/blog/css-best-practices/)」（Kinsta、2024年8月22日）を参照した。今回の設計では、スタイルシートの一貫性・セクション化・コメント、外部CSSの利用、DRY、クラス中心の再利用、BEMなどの明示的な命名規約、フォーカスを含むアクセシビリティ、`!important`の抑制、Flexboxを優先するレイアウトを採用する。静的PWAの現行構成では、プリプロセッサや大規模フレームワークを追加せず、標準CSSの明示的な読み込み順とカスタムプロパティで同等の保守性を確保する。

## テンプレート構造の所見

`index.html`には、ダッシュボード、設定、振り返り、試合詳細を含む画面テンプレートが集約されている。既存の`card`、`insights-section`、`library-grid`、`sl-section`などは再利用できる土台である一方、見出し・ツールバー・操作群・空状態のラッパーが画面ごとに異なるため、標準レイアウト部品へ統一する。

インライン指定で最も多いのは`font-size`（193件）、`display`（171件）、`color`（147件）、`gap`（117件）、`margin-bottom`（88件）、`padding`（87件）である。第1移行対象は、画面内で繰り返すFlex・Gridの整列、間隔、文字の役割、表面・境界の指定とし、JavaScriptが動的に与える一回限りの位置・寸法は動作リスクを避けて当面維持する。
