07 / COMPONENT SYSTEM

業務UIを支える6つの共通部品

個別画面のレイアウトではなく、情報と操作の責務を持つ部品として設計する。

c-form-field

フォーム項目

ラベル・補足・入力・エラーを一体化。設定画面の空白と行ずれを防ぐ。

c-fieldset

入力グループ

複数入力の意味をまとめ、招集・出欠の説明とエラーを整理する。

c-roster-row

名簿行

選択・選手識別・出欠状態を分離し、checkboxと名前の重なりを防ぐ。

c-practice-card

練習カード

情報・統計・操作・詳細を分け、操作ボタンとバッジの衝突を防ぐ。

c-data-list

データリスト

狭幅で縮めるべきでない表を、主要指標の縦リストとして再配置する。

c-modal

モーダル

ヘッダー・単一スクロール本文・固定フッターを分離し、保存操作を守る。

練習管理への適用LIVE STRUCTURE
c-practice-card

日付、統計、操作、詳細を別スロットにして、カード内の競合を局所化する。

c-roster-row

名簿では選手名と出欠選択を別のレイアウト領域に置く。

c-modal

長い出欠名簿でも保存操作を常に確認できる構成にする。

部品の責務を固定することで、カード幅・名簿量・画面幅が変わっても操作の優先順位を維持する。
DESIGN RULE

不具合は「画面のCSS」ではなく、対応する部品の構造・トークン・検証ケースへ戻して解決する。
