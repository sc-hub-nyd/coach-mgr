# CoachMgr P10: 安全なGAS同期API

このディレクトリの `Code.gs` は、CoachMgrのクラウド同期を**安全モード（POST認証）**へ移行するためのGoogle Apps Scriptテンプレートです。従来のGET受信では認証トークンがURLに含まれ、履歴・プロキシログ・アクセスログに残るおそれがあります。このテンプレートでは、読み取り・書き込みをともに `text/plain` のPOST本文で受け付け、GETではチームデータを返しません。

| 項目 | P10安全モード |
|---|---|
| API操作 | `pull` と `push` をPOST本文で受信 |
| 認証トークン | Script Propertiesにのみ保存し、URLへ載せない |
| 同期先 | 明示指定した既存シートのみ。名前の妥当性も検査 |
| 競合書込み | Script Lockで直列化 |
| データ完全性 | SHA-256チェックサムを保存・照合 |
| スナップショット | 1セル上限を超えるJSONをチャンク分割して保存 |

## 導入

Apps Scriptで新しいスタンドアロンプロジェクトを作成するか、対象スプレッドシートに紐付くプロジェクトを開きます。`Code.gs` の内容を貼り付け、必要であれば `appsscript.json` の設定を反映します。コードやGit履歴に認証トークン・スプレッドシートIDを直接書き込まないでください。

次に、Apps Scriptの**プロジェクトの設定**からScript Propertiesを設定します。`COACHMGR_AUTH_TOKEN` には24文字以上のランダムな文字列を設定してください。スタンドアロンプロジェクトでは、`COACHMGR_SPREADSHEET_ID` に対象スプレッドシートIDを設定します。スプレッドシートに紐付くスクリプトではこの値は不要です。

| Script Property | 必須 | 内容 |
|---|---:|---|
| `COACHMGR_AUTH_TOKEN` | はい | 24文字以上のランダムな秘密値。アプリの「認証トークン」と同じ値 |
| `COACHMGR_SPREADSHEET_ID` | スタンドアロン時 | 同期データを保存するスプレッドシートID |

その後、**デプロイ > 新しいデプロイ > ウェブアプリ**を選びます。必要なスプレッドシートアクセス権を持つデプロイアカウントとして実行し、アプリの利用者がPOSTを送れる共有範囲を選択します。表示された `/exec` URLをCoachMgrの「Web API URL」へ設定してください。初回デプロイ前に、同期先に使用するシートをあらかじめ作成してください。

## 切替手順

CoachMgrを `v1.9.0` 以降へ更新した後、設定画面でWeb API URL、シート名、認証トークンを入力します。「同期プロトコル」を**安全モード（POST認証・推奨）**に変更して保存してください。最初に「クラウドへ送信」を実行し、次に端末バックアップを作成してから「クラウドから復元」を確認します。安全モードでGETリクエストを行う必要はありません。

旧スクリプトが残っている間だけは、CoachMgr側の「互換モード（旧GAS用）」を明示選択できます。このモードでは認証トークンがURLクエリに含まれるため、P10テンプレートのデプロイ確認後に速やかに安全モードへ切り替えてください。

## 受け入れ確認

正しいトークンで `pull` と `push` が成功し、誤ったトークンではどちらも `status: "error"` と `code: "unauthorized"` が返ることを確認します。URLクエリに `authToken` を付けたGETは、データを返さず `method_not_allowed` になることも確認対象です。Google Apps ScriptのWeb App、Properties Service、Content Serviceの仕様は、P10の外部参照メモを確認してください。

## ロールバック

デプロイ直後に問題が起きた場合は、CoachMgr側だけを一時的に「互換モード」へ戻します。旧APIはトークン漏えいリスクが残るため、長期的なロールバックとしては使用せず、GASの実行ログ・Script Properties・対象シート名を確認して安全モードを復旧してください。トークンを誤送信・共有した可能性がある場合は、直ちにScript Propertiesの値を再発行し、CoachMgrの端末設定を更新します。
