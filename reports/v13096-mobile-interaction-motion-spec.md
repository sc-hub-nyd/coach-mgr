# CoachMgr モバイル操作アニメーション仕様

**版:** Draft 1.0
**作成日:** 2026-08-20
**対象:** モバイルPWAのボトムナビゲーション、モーダル、コンテキストバー、共通ボタン
**前提:** 本書は実装前の仕様であり、アプリ本体・PWAキャッシュ世代・公開版は変更しない。

## 1. 目的と原則

本仕様の目的は、CoachMgrをスマートフォンで操作した際に、操作結果を**速く・迷いなく・少し楽しく**伝えることである。アニメーションは装飾ではなく、タップできたこと、選択先が変わったこと、モーダルが開閉したことを示すためにのみ用いる。試合・練習の現場では、ページ全体の派手な移動や、入力待ちを感じさせる長いアニメーションを使わない。

ボトムナビの主役は、選択面、塗りアイコン、太字ラベル、短いブランドラインである。Kinetic Lens Dockを採用する場合でも、弧状アクセントと「キックの余韻」は選択後に一度だけ出る補助表現に限定する。タブ間を横断する液体表現、無限ループ、反復バウンス、背景パララックスは導入しない。

ユーザー操作で発生する非必須の動きは停止可能でなければならないため、OSの `prefers-reduced-motion` とアプリ内の動きを減らす設定の両方を尊重する。[1] [2] 動きを無効にしても、選択・展開・同期・成功の状態は、色、面、太さ、ラベル、ARIA状態によって同じく伝わることを必須とする。

## 2. 既存トークンの採用方針

現行の `CSS/tokens.css` は、以下の共通トークンをすでに定義している。本仕様はこれらを継続利用し、画面固有の直書き時間・直書きイージングを導入しない。

| 種別 | 現行トークン | 値 | 採用範囲 |
|---|---|---:|---|
| 速い状態変化 | `--duration-fast` | 140ms | 押下解除、アイコンの太さ・色、短いラインの出現 |
| 標準状態変化 | `--duration-base` | 200ms | 選択面の表示、タブ切替、コンテキストバーの出現 |
| 入場・減速 | `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | 見える状態へ収束する面・モーダル・バー |
| 連続変化 | `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | 色・影の往復、閉じる処理 |
| 控えめな弾み | `--ease-spring` | `cubic-bezier(0.2, 0.8, 0.25, 1)` | 選択面とアイコンの小さなキネティック反応 |

実装時には、次の二つだけを**モーション層の共通トークン**として追加する。いずれも個別コンポーネントの値ではなく、既存トークンと同じ `tokens.css` に置く。

```css
:root {
  --duration-micro: 80ms;
  --duration-sheet: 260ms;
}
```

`--duration-micro` はタップ開始と軽い視覚フィードバック、`--duration-sheet` はボトムシートのように位置変化を伴う面の開閉だけに用いる。260msを超える操作結果のアニメーションは、読み物や説明コンテンツ以外では導入しない。

## 3. 時間とイージングの全体規則

| 時間帯 | 用途 | 適用するイージング | 許容する変化 |
|---|---|---|---|
| **80ms** | タップ開始、短い軌道アクセントの点灯 | `--ease-out` | `opacity`、1px以下の影、`scale`の開始 |
| **140ms** | タップ解除、アイコン・ラベル・ブランドライン | `--ease-out` | `opacity`、`color`、`background-color`、`transform` |
| **200ms** | 選択面の収束、コンテキストバーの表示 | `--ease-spring` または `--ease-out` | `opacity`、`transform`、面の色・影 |
| **260ms** | ボトムシートの開閉 | 開く: `--ease-out`、閉じる: `--ease-in-out` | `opacity`、`translateY` |
| **1ms** | 動きを減らす設定 | なし | 終了状態を即時に表示 |

状態を表すアニメーションは、**opacity、transform、color、background-color、box-shadow**に限定する。`width`、`height`、`left`、`top`、`margin`を連続的に変えてレイアウトを動かしてはならない。`transition: all` も禁止する。これにより、4タブ・5タブへのロール切替、Safe Area、文字拡大時に意図しないレイアウト変動を避ける。

## 4. ボトムナビゲーションの操作仕様

### 4.1 基本状態

各項目のタップ領域は現行通り44px以上とする。非選択項目は補助文字色・アウトラインアイコン・透明面、選択項目はチームカラー由来のレンズ面・太字ラベル・強調アイコン・ブランドラインで表す。アニメーションがなくても、選択状態を判断できなければならない。

| 操作・状態 | 開始タイミング | 時間 | イージング | 視覚反応 | 実装上の注意 |
|---|---|---:|---|---|---|
| タップ開始 | `pointerdown` | 80ms | `--ease-out` | 押したタブを `scale(0.98)`、`translateY(1px)`。影を浅くする。 | `is-pressing` は既存のグローバル処理に合わせる。 |
| タップ解除 | `pointerup` / `pointercancel` | 140ms | `--ease-out` | 通常の大きさ・影へ戻す。 | 遷移失敗時にも必ず戻す。 |
| 未選択→選択 | ルート確定と同フレーム | 200ms | `--ease-spring` | レンズ面を `opacity: 0 → 1`、`scale(0.94) → 1`。 | 横移動する共有インジケーターは初期実装で使わない。 |
| 選択→未選択 | ルート確定と同フレーム | 140ms | `--ease-out` | レンズ面をフェードアウトし、アイコン・ラベルを通常トーンへ戻す。 | 新旧の選択面が重なり続けない。 |
| アイコン強調 | 選択面の表示と同時 | 140ms | `--ease-out` | 選択アイコンのみ `translateY(-1px)`、塗り/太線、ブランド色へ変化。 | アイコンがラベルへ重ならない範囲に限定する。 |
| ブランドライン | 選択面の表示と同時 | 140ms | `--ease-out` | `scaleX(0.6) → scaleX(1)`、`opacity: 0 → 1`。 | 高さは2〜3px、選択タブの境界内に収める。 |
| キックの余韻 | 新しい選択が確定した直後 | 80ms点灯 + 140ms消灯 | `--ease-out` | 弧状アクセントを一度だけ表示し、透明化する。 | `::after` 一つで表し、反復・ループさせない。 |

### 4.2 「その他」タブとモーダルの同期

「その他」はナビゲーションの選択ではなく、モバイル用メニューを開く展開操作である。現行の `is-expanded` と `aria-expanded` の同期を維持し、視覚状態だけを下表の仕様へ統一する。

| 操作・状態 | 時間 | イージング | 視覚反応 | ARIA・フォーカス |
|---|---:|---|---|---|
| 「その他」押下 | 80ms | `--ease-out` | 押下状態を表示する。 | `aria-expanded` は表示確定時に `true`。 |
| 展開状態への切替 | 200ms | `--ease-spring` | レンズ面・太字・ブランドラインを選択タブと同じ意味で表示する。 | 現行のMutationObserver同期を維持する。 |
| オーバーレイ表示 | 140ms | `--ease-out` | `opacity: 0 → 1`。 | モーダルがフォーカスを受け取る。 |
| ボトムシート表示 | 260ms | `--ease-out` | `translateY(1rem) → translateY(0)` と `opacity: 0 → 1`。 | 操作可能になるのはフォーカス移動後。 |
| 閉じる | シート180ms / オーバーレイ120ms | `--ease-in-out` | シートは下へ戻り、オーバーレイは消える。 | 閉じた後にトリガーへフォーカスを戻す。 |

現行の `.hidden { display: none !important; }` をそのまま付け外しするだけでは、閉じるアニメーションは成立しない。実装時は `is-opening`、`is-open`、`is-closing` の状態を持たせるか、`hidden` 属性をトランジション完了後に付与する。ただし、アニメーション完了を待つ間もダイアログの操作可能性・フォーカストラップ・Escapeキー処理を損なわない。

### 4.3 画面遷移とコンテキストバー

CoachMgrのルート切替は、ボトムナビからの即時操作を最優先する。コンテンツ全体の横スライド、カードの順次出現、パララックスは使わない。選択タブの反応そのものが遷移完了の主要な手がかりとなる。

| 対象 | 時間 | イージング | 規則 |
|---|---:|---|---|
| 通常ルート切替 | 0ms | なし | コンテンツは即時更新する。ボトムナビの選択面だけを動かす。 |
| 再描画後の主要領域 | 最大120ms | `--ease-out` | 内容が置換される場合のみ、`opacity: 0 → 1` を一度だけ許可する。読み込み待ちを隠すためには使わない。 |
| モバイルコンテキストバー表示 | 200ms | `--ease-out` | `opacity` と `translateY(0.25rem → 0)` のみ。 |
| モバイルコンテキストバー非表示 | 140ms | `--ease-in-out` | `opacity` と `translateY(0 → 0.25rem)` のみ。 |
| 戻るボタン押下 | 80ms / 140ms | `--ease-out` | 共通ボタンの押下・復帰を適用し、画面全体はスライドさせない。 |

## 5. 共通操作・フィードバック

| コンポーネント | 操作 | 時間・イージング | 視覚仕様 |
|---|---|---|---|
| 標準ボタン | 押下→解除 | 80ms → 140ms、`--ease-out` | `scale(0.98)` と押下影。テキスト・アイコンの位置は変えない。 |
| アイコンボタン | 押下→解除 | 80ms → 140ms、`--ease-out` | 背景面と影を変化。危険操作は色役割を保持し、揺らさない。 |
| ステータスタグ | ホバー可能環境でのフォーカス | 140ms、`--ease-out` | 面の明度・アウトラインを変える。点滅しない。 |
| 更新通知ボタン | 更新可能→適用中→完了 | 140ms、200ms、0ms | 成功トーンを維持。同期中は短い回転ではなく、ラベル・aria-liveで状態を伝える。 |
| 通知バッジ | 新着到着 | 140ms、`--ease-spring` | `scale(0.85) → 1` を一度のみ。反復点滅は禁止。 |
| エラー | 表示 | 0ms | 色、アイコン、テキストを即時表示。エラーを揺らして表現しない。 |
| 成功 | 完了 | 140ms | 色・アイコンの変化のみ。自動消失する場合は十分な表示時間を別途確保する。 |

## 6. 動きを減らす設定

現行では `prefers-reduced-motion: reduce` および `data-reduce-motion="true"` の両方で、`--duration-fast` と `--duration-base` を1msへ短縮している。この仕組みを維持し、追加する `--duration-micro` と `--duration-sheet` も同じ条件で1msに上書きする。

```css
@media (prefers-reduced-motion: reduce) {
  :root {
    --duration-micro: 1ms;
    --duration-fast: 1ms;
    --duration-base: 1ms;
    --duration-sheet: 1ms;
  }
}

:root[data-reduce-motion="true"] {
  --duration-micro: 1ms;
  --duration-fast: 1ms;
  --duration-base: 1ms;
  --duration-sheet: 1ms;
}
```

この設定では、動きだけを消し、選択面、色、アイコン太さ、ラベル太さ、`aria-expanded`、モーダルの開閉結果は即時に反映する。WCAGの解説でも、OSまたはユーザーエージェントの動き削減設定を尊重し、操作に伴う不要なモーションを抑制することが示されている。[1] [2]

## 7. 実装ガードレール

1. **すべての時間値とイージングはトークンから参照する。** コンポーネントCSSやJavaScriptに `200ms`、`cubic-bezier(...)` を直書きしない。
2. **アニメーションは状態確定を遅らせない。** `aria-selected` 相当の選択クラス、`aria-expanded`、フォーカス移動、データ表示は、見た目の完了を待たずに正しい状態へ更新する。
3. **ナビゲーションと操作を混同しない。** タブは画面移動のみを担当し、記録追加などのアクションを大きく浮かせる場合は独立した操作として扱う。
4. **選択面はタブ境界を越えない。** ロールによる4/5タブ切替や文字拡大でも、隣接タブの視覚的・実際のタップ領域を侵食しない。
5. **Safari/iOSを含めてフォールバック可能にする。** `backdrop-filter` が使えない場合でも、不透明な `--glass-surface-strong` と選択面により状態が見分けられるようにする。
6. **回転・点滅・無限ループを通常の完了表現に使わない。** 同期、保存、更新は進行文言・`aria-live`・決定的な状態表示を優先する。

## 8. 検証基準

| 層 | 検証項目 | 合格基準 |
|---|---|---|
| トークン | モーション値 | 新規の時間・イージングは `tokens.css` のみで定義される。 |
| 静的契約 | 禁止事項 | `transition: all`、無限ループ、画面・部品層の固定色を増やしていない。 |
| 状態契約 | ナビ | `.active` と `.is-expanded` が同じ選択状態の意味トークンを用い、`aria-expanded` とモーダル可視状態が同期する。 |
| 動きを減らす設定 | OS / アプリ設定 | すべての非必須モーションが1msになり、最終状態が即時に確認できる。 |
| 手動操作 | タップ | `pointerdown`、`pointerup`、`pointercancel` 後に押下状態が残らない。 |
| 手動操作 | キーボード | Tabで見えるフォーカスが維持され、Space/Enterでタブと「その他」を操作できる。 |
| 手動操作 | モーダル | 開閉中・閉じた後のフォーカストラップ、Escape、トリガーへのフォーカス復帰が正常である。 |
| 実機 | 表示 | ライト/ダーク、チームカラー変更、4/5タブ、Safe Area、横表示、屋外で選択状態を判別できる。 |

実装時には、P47へモーション・トークン・動き削減設定の静的契約を追加し、P54へ「その他」タブとボトムシートの展開・閉じる状態契約を追加する。実装を伴うリリースでは、アプリ版、Service Workerキャッシュ世代、P47/P49/P54の期待値を同時に更新し、全契約テストを実行する。
