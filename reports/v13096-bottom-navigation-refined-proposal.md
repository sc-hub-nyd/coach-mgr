# CoachMgr ボトムナビゲーション改善提案書（ブラッシュアップ版）

**作成日:** 2026-08-20
**対象:** CoachMgr モバイル用ボトムナビゲーション
**位置付け:** 実装前の設計提案。アプリケーションコード、PWA世代、公開版は変更しない。

## 結論

添付提案の「**モーフィング・ウェーブドック**」は、CoachMgrのモバイル体験を高める方向性として妥当です。ただし、試合・練習の現場で短時間に操作する業務PWAでは、波そのものを主役にしたり、タブ間をつなぐ液体アニメーションを常時表示したりする設計は採用しません。代わりに、**選択タブの面が短時間で“せり上がる”ように見える、静的優先の「Adaptive Wave Dock」**へ置き換えることを推奨します。

この案は、既存の5分割レイアウト、`--color-surface-selected`、`--color-brand`、`--tap-target`、`--duration-base`をそのまま基盤に使います。見た目をチームカラーに追随させながら、選択状態を**色・塗り面・アイコンの太さ・ラベル**の四重の手がかりで伝え、動きを無効化する利用者にも同じ情報を提供します。現行の「その他」ボタンが展開時に選択面へ変わる挙動も維持し、モーダルとのARIA同期を壊しません。

> **採用判断:** 案2を採用。ただし「液体がタブ同士を結合する演出」ではなく、「各タブの内部に収まる、控えめな選択面の変形」として実装する。案4のソフトリップルは、タップ時の補助的なフィードバックとしてのみ統合する。

## 1. 添付提案の評価とCoachMgr向けの調整

添付資料は、屋外利用時の視認性、短い応答時間、44×44px以上の操作領域を重視しており、CoachMgrの利用文脈と一致しています。現在の実装も、`min-height: var(--tap-target)` と `--tap-target: 44px`、Safe Areaを加味した64pxのナビ領域をすでに備えています。したがって、改善の中心は「ナビを大きく作り直す」ことではなく、**状態の識別性と触感の一貫性を高めること**です。

| 添付案 | 評価 | CoachMgrでの扱い | 理由 |
|---|---|---|---|
| 案1: メタボール・インジケーター | 不採用 | 実装しない | タブを横断して面が伸びると、画面遷移中の操作位置が曖昧になり、業務操作の即時性を下げる。 |
| 案2: モーフィング・ウェーブドック | **採用・再定義** | Adaptive Wave Dockとして採用 | 選択状態の面・色・階層を明瞭にできる。変形は各タブ内に閉じ、移動量を最小化する。 |
| 案3: 独立型リキッドポッド | 不採用 | 実装しない | 4/5タブで横幅が変わるロール別構成と相性が悪く、選択ポッドの移動が情報の見通しを損ねる。 |
| 案4: ソフトリップル・フロスト | **部分採用** | `is-pressing` の瞬間フィードバックへ限定 | 現在の押下状態の仕組みを活かせる。ただし、押下後に残る波紋や広範囲の発光は採用しない。 |

## 2. 推奨デザイン: Adaptive Wave Dock

### 2.1 目指す体験

Adaptive Wave Dockは、ナビ全体を装飾するのではなく、**選択タブだけをわずかに持ち上がった柔らかい面として表示する**ものです。非選択タブは透明な面と落ち着いた補助文字色を維持します。選択タブはチームカラー由来の選択面、ブランド色のアイコンとラベル、わずかな内側ハイライトを用います。暗色テーマでは同じ意味トークンが濃い選択面へ切り替わるため、赤系の既定テーマに限定されず、利用チームのカラー変更にも追随します。

外部の色や固定の影を追加しないことが重要です。既存のトークンである `--color-surface-selected`、`--color-brand`、`--glass-surface-strong`、`--focus-ring`、`--liquid-veil` を意味の所有者として用い、画面・部品層の直接指定色ゼロという既存ルールを維持します。

### 2.2 視覚構造

| 要素 | 非選択 | 選択 | 「その他」展開中 | 意図 |
|---|---|---|---|---|
| タブ面 | 透明 | `--color-surface-selected` | `--color-surface-selected` | 選択状態を塗り面で即時に識別する。 |
| アイコン・ラベル | `--text-secondary` | `--color-brand`、700 | `--color-brand`、700 | 色だけでなく太さと文字で状態を重ねる。 |
| 上端のウェーブ | 非表示 | タブ幅の60%以内、2px程度の短いアクセント | 同左 | 「どこが選択中か」を補強する。隣接タブへまたがらない。 |
| 押下 | なし | なし | なし | 選択そのものには常時の動きを使わない。 |
| 押下フィードバック | `is-pressing`時のみ面を微小に沈める | 同左 | 同左 | タップ完了前の手がかり。リップルを永続させない。 |
| キーボードフォーカス | 共通フォーカスリング | 共通フォーカスリングに加えて選択面を維持 | 共通フォーカスリングに加えて展開面を維持 | 選択状態とフォーカス状態を混同しない。 |

### 2.3 形状と寸法

現行のSafe Area対応と下端固定は維持します。高さは通常時 `calc(64px + var(--safe-bottom))` のままとし、項目ごとのタップ可能領域は44px未満にしません。44pxはCoachMgrのプロダクト要件であり、WCAG 2.2のAA最小要件である24×24 CSS pxを上回ります。隣接するタブを近接配置するボトムナビでは、単に間隔で例外を満たすより、各タブ自体を十分な大きさにする方が操作ミスを抑えやすい設計です。[1]

選択面は `--control-radius` を使い、現行と同じ8px相当の角丸を維持します。ナビ全体は `--radius-lg` の上側角丸を維持し、「その他」モーダルのボトムシートと同じ大きな曲率へ揃えます。ウェーブの見た目は `::before` 疑似要素で作り、タブ領域外へ出さず、`border-radius: var(--radius-pill)` の短いラインに留めます。これにより、液体表現を取り入れつつ、角丸規則とタップ領域の判定を複雑にしません。

### 2.4 モーション方針

現在定義済みの `--duration-fast: 140ms`、`--duration-base: 200ms`、`--ease-spring` を用います。選択面の表示は **200ms以内**、押下フィードバックは **140ms以内**とし、アイコンの位置移動は行いません。表示上の変化は背景色、短いウェーブ、1px以下の陰影変化に限ります。

`prefers-reduced-motion: reduce` では既存のトークンが1msに短縮されるため、その仕組みを守ります。新しい個別アニメーションや無限ループは導入しません。試合中でも認知負荷を上げず、動きを好まない利用者にも同じ選択情報を届けるためです。

## 3. アクセシビリティと状態設計

ボトムナビはページ内の主要ナビゲーションであり、視覚的な選択状態だけでは不十分です。現在の `<nav aria-label="主要ナビゲーション">`、各リンクの固有ラベル、`その他`ボタンの `aria-controls` と `aria-expanded` を維持します。「その他」の展開時には `is-expanded` と `aria-expanded="true"` が同期する現行実装を変更しません。

キーボードで操作できる項目には、常に可視のフォーカス表示が必要です。WCAG 2.2は、キーボード操作可能なUIに視認可能なフォーカス表示を求めています。[2] 現行の共通規則である3pxの `--focus-ring` と2pxのオフセットを維持し、ウェーブや影でフォーカスリングを置き換えないものとします。将来的にフォーカス外観の厳格な達成を目指す場合も、2px相当以上の周囲領域と、フォーカス前後で3:1以上の変化コントラストを担保しやすいアウトライン方式を優先します。[3]

| 状態 | クラス・ARIA | 視覚要件 | 操作・検証要件 |
|---|---|---|---|
| 非選択 | クラスなし | 補助文字色、透明面 | 現行ルートへの遷移ができる。 |
| 選択 | `.active` | 選択面、ブランド色、太字、短いウェーブ | ルート遷移後に該当項目のみ選択状態になる。 |
| その他展開 | `.is-expanded`、`aria-expanded="true"` | 選択と同じ意味の面・色・ウェーブ | ボトムシート表示と状態が双方向に同期する。 |
| ホバー可能環境 | `:hover` | 選択面とは異なる弱い面変化 | タッチ環境にホバー表現を強制しない。 |
| 押下 | `.is-pressing`、`:active` | 140msの微小な沈み込みのみ | タップの結果が確定するまでにフィードバックが見える。 |
| フォーカス | `:focus-visible` | 3pxアウトライン、2pxオフセット | Tab操作で全タブの位置を視認できる。 |
| 動きを減らす設定 | `prefers-reduced-motion` | 最終状態を即時表示 | 状態の情報量が失われない。 |

## 4. 実装仕様

### 4.1 変更対象と変更しない対象

| 区分 | 対象 | 方針 |
|---|---|---|
| CSS | `CSS/base.css` のモバイル用 `.c-bottom-nav` 規則 | 選択面、疑似要素、押下・ホバー・フォーカスの状態規則を追加する。既存の固定位置、Safe Area、5等分は維持する。 |
| トークン | `CSS/tokens.css` | 必要な場合のみ `--bottom-nav-indicator-*` を既存意味トークンから合成して追加する。固定色や固定影は導入しない。 |
| HTML | `index.html` | 原則変更しない。現在の5項目、ARIAラベル、`aria-controls`を保持する。 |
| JavaScript | `app.js` | 原則変更しない。現行の `syncBottomNavMoreState()` による展開同期をそのまま使う。 |
| モーダル | `modal-mobile-more` | シートの角丸・選択面方針は現在の統一仕様を維持し、ナビと同じ意味トークンを参照する。 |
| PWA | `version.js`、`sw.js` | コード採用時のみバージョンとキャッシュ世代を同時更新し、更新通知を確認する。設計提案のみでは更新しない。 |

### 4.2 CSS設計の要点

疑似要素はタブ自身に限定します。選択面を共有の可動インジケーターで横移動させる実装は、保護者モードでコーチ専用項目が非表示になる4分割状態に対応しにくく、状態計算とレイアウト崩れのリスクを増やします。各タブが自ら選択面を持つ構造なら、4項目・5項目の両方で自然に幅へ追随します。

```css
/* 実装イメージ。値は既存トークンのみから構成する。 */
.c-bottom-nav__item {
  position: relative;
  isolation: isolate;
}

.c-bottom-nav__item::before {
  content: '';
  position: absolute;
  inset: 4px 1px;
  border-radius: var(--control-radius);
  background: var(--color-surface-selected);
  opacity: 0;
  transform: scale(0.96);
  transition: opacity var(--duration-fast) var(--ease-out),
              transform var(--duration-base) var(--ease-spring);
  z-index: -1;
}

.c-bottom-nav__item.active::before,
.c-bottom-nav__item--more.is-expanded::before {
  opacity: 1;
  transform: scale(1);
}
```

実装時は、既存の `.active` と `.is-expanded` の背景指定を上記の疑似要素へ集約するか、現在の面と二重にならない形で調整します。`z-index`、`isolation`、`overflow`の扱いは既存のリンククリック領域を狭めないことを最優先とし、疑似要素に `pointer-events: none` を付けます。

## 5. 契約テストと受入基準

本改善は視覚表現だけに見えますが、選択状態・モーダル同期・ロール別レイアウトが関係するため、既存のP47およびP54に契約を追加するべきです。次の基準を満たした時点で採用完了とします。

| テスト層 | 受入基準 | 主な対象 |
|---|---|---|
| 静的契約 | 画面・部品層の固定色が0件のままである。選択面・ブランド色・半径・時間はトークンのみを参照する。 | P47 |
| 状態契約 | `.active` と `.is-expanded` が同じ選択面の意味トークンを利用し、`aria-expanded`がモーダル表示状態と同期する。 | P47、P54 |
| 形状契約 | ナビ全体は `--radius-lg`、項目と選択面は `--control-radius`、ウェーブのみ `--radius-pill` を使う。 | P47 |
| サイズ契約 | すべての可視タブの最小操作高さは44px以上で、保護者モードの4分割時にも縮小しない。 | P47、新設ケース |
| キーボード契約 | `:focus-visible` の共通アウトラインを削除・隠蔽しない。 | P47 |
| 動きの契約 | 新たな無限アニメーションを入れず、`prefers-reduced-motion`時のトークン短縮を回避しない。 | P47 |
| 手動回帰 | ライト・ダーク、チームカラー変更後、4/5タブ、Safe Area端末、横表示、モーダル開閉、Tab・Enter・Escapeで確認する。 | 実機確認 |

## 6. 実装ロードマップと採用判断

| 段階 | 成果物 | 完了条件 | リスクを抑える要点 |
|---|---|---|---|
| A. モック | 静的CSSのみの選択面・ウェーブ | 4/5タブ、ライト/ダークで見切れ・二重背景なし | JavaScript・モーダルを変えない。 |
| B. 状態統合 | 押下、ホバー可能環境、フォーカスの状態規則 | 状態が相互に打ち消し合わない | `:focus-visible`を影や色変化で代替しない。 |
| C. 契約追加 | P47/P54の検証を拡張 | 全45件以上の契約が成功 | 現行PWA世代の期待値を同期する。 |
| D. リリース | バージョン、SWキャッシュ、変更履歴 | オフライン表示・更新通知・公開環境で確認 | JS/CSS両方がキャッシュ更新対象であることを確認する。 |
| E. 実機評価 | 利用者の屋外・片手利用での評価 | 誤タップ、選択状態の誤認、その他メニューの発見性に問題なし | 見た目の好みではなく、操作完了時間と迷いの有無で判断する。 |

最初の実装では、中央タブの浮き上がり、タブ間を横断する液体接続、バウンス、常時アニメーションは入れません。これらは検証後にもなお「その他」の発見性または選択状態の認知を明確に改善する根拠が得られた場合に限り、別の実験項目として検討します。
