# Tabler Icons 移行ロードマップ

**対象:** CoachMgr v1.30.82以降
**目的:** Font Awesome依存をTabler Iconsへ置き換え、サッカー文脈を強めつつ、独自SVG・Canvas作図・PWA・アクセシビリティを維持する。

## 到達像

CoachMgrでは、**チーム固有の概念は既存の既定チームカスタムSVG**、**汎用の業務操作とサッカー補助語彙はTabler Icons**、**戦術そのものはCanvas図形**という三層を基本とします。Font AwesomeのCDN参照は最終的に削除し、Tabler Webfontをローカル配信・Service Worker precacheへ組み込みます。

> TablerはMITライセンス、24pxグリッド、2pxストローク、Webfont／SVGの提供を公式に案内しています。[1] [2] [3]

## フェーズ一覧

| フェーズ | 主目的 | 主要成果物 | 完了条件 |
|---|---|---|---|
| P0 | 移行基盤と安全網の整備 | ローカルTabler Webfont、対応表、P42契約 | Tablerがオフラインで読み込め、旧・新アイコンを並行検証できる |
| P1 | アプリシェルとダッシュボードの置換 | ナビ、トップバー、モバイル導線、ランキングのTabler化 | 主要導線がTabler表示となり、サッカー語彙が統一される |
| P2 | 機能画面と動的生成UIの置換 | 試合、練習、選手、メニュー、戦術、作図の変換 | 主要機能画面のFont Awesomeクラスがゼロになる |
| P3 | 設定・同期・例外の置換と撤去 | 設定、同期、空状態、競合ダイアログ、CDN削除 | Font Awesome依存ゼロ、PWA・アクセシビリティ品質ゲート合格 |
| P4 | SVGの追加整備と運用定着 | カスタムSVG追加候補、アイコン台帳、レビュー規約 | 新規実装が役割表・自動検証に従う |

## P0: 移行基盤と安全網

P0は見た目を大きく変えず、以後の全置換を安全にするための基盤フェーズです。Font AwesomeとTablerを一時的に共存させますが、画面ごとに二重表示はしません。

| 区分 | 具体的タスク | 成果物・検証 |
|---|---|---|
| パッケージ固定 | `@tabler/icons-webfont`を固定版（調査時点では3.46.0）で取得し、CSSとWOFF2を`assets/vendor/tabler-icons/`へ配置する | バージョン・ライセンスをヘッダまたは台帳に記録する |
| PWA組込み | `index.html`へローカルCSSを追加し、`sw.js`のprecacheへCSSとWOFF2を追加する | 機内モード相当でもアイコンフォントが表示できる |
| 共通基盤 | `.ti`のサイズ、色、縦位置、ボタン内余白を`CSS/icon-system.css`へ定義する | `currentColor`、ライト／ダーク、既存ボタンサイズと整合する |
| 対応表 | Font Awesome名 → Tabler名の明示的なマッピング辞書を作る | `futbol→ball-football`、`bullseye→target`、`shoe-prints→shoe`等を含む |
| 変換補助 | 置換候補を検出する監査・変換スクリプトを作る。曖昧な名称は自動変換せずレビュー一覧へ出す | `fa-*`の未対応名、旧CDN、新旧混在を検出する |
| 契約テスト | P42としてローカルTablerの読み込み、サッカー主要語彙、アクセシブルな単独操作を検証する | 構文・契約・レスポンシブ検証が成功する |

**P0のリスク対策:** CSSクラスの衝突を避けるため、Tablerは`ti ti-*`、カスタムSVGは`c-icon`、Canvasは`data-tool`という既存の分離を崩しません。Font Awesomeを削除するのはP3完了時だけです。

## P1: アプリシェルとダッシュボードの置換

P1では、利用頻度が高く、Tablerのサッカー語彙の価値が最も分かりやすい画面を優先します。利用者が毎日見る導線で、Tablerの線幅・トーンを確認します。

| 対象 | 具体的タスク | Tablerの代表候補 | 検証 |
|---|---|---|---|
| サイドナビ | ホーム、試合、練習、メニュー、戦術、選手、設定のアイコンを置換 | `home`、`trophy`、`cone`、`notebook`、`soccer-field`、`users-group`、`settings` | デスクトップ・横向き・縦向きで揃う |
| モバイルナビ | ボトムナビ、Moreシート、戻る、閉じる、メニューのアイコンを置換 | `home`、`trophy`、`cone`、`file-text`、`menu-2`、`arrow-left`、`x` | 44px以上のタップ領域とaria-labelを確認 |
| トップバー | モード、テーマ、同期、更新通知、クラウド状態を置換 | `eye`、`sun`／`moon`、`cloud-download`、`refresh`、`info-circle` | 状態に応じた色・ラベルが維持される |
| ダッシュボード | 試合、得点、失点、ランキング、アシスト、出席、アラートを置換 | `ball-football`、`shield`、`target`、`shoe`、`users`、`alert-triangle` | 2列ランキング、長い日本語ラベル、ライト／ダークを確認 |
| 役割の明確化 | 既存カスタムSVGと競合する導線を整理し、固有概念はSVGを優先する | `soccer-field`は戦術、`ball-football`は得点・試合の補助 | 同じ概念に複数のアイコンを使わない |

**P1の完了条件:** アプリシェルとダッシュボードに残るFont Awesomeクラスがゼロで、利用者が視認する主要導線のサッカー語彙がTablerへ統一されること。

## P2: 機能画面と動的生成UIの置換

P2は件数が多いフェーズです。HTMLだけでなく、JavaScriptテンプレート文字列で生成するアイコンを対象に含めます。画面単位で置換・テスト・レビューを完結し、全体置換による事故を避けます。

| 対象モジュール | 具体的タスク | 特に確認する操作 |
|---|---|---|
| `matches.js` | 試合一覧、ピリオド、得失点、交代、PK、動画分析、共有、削除を置換 | 結果バッジ、交代、試合内サイドパネル、YouTube識別 |
| `practices.js` | 練習一覧、出欠、メニューアサイン、振り返り、追加・編集を置換 | 出欠状態、練習カテゴリ、フィルター、空状態 |
| `players.js` | 選手一覧、プロフィール、育成ノート、スタッツ、CSVを置換 | 選手追加、削除、成長記録、指標カード |
| `library.js` | 練習ライブラリ、メディア、評価、アサイン、検索を置換 | 参考動画、スター、フィルター、複製 |
| `tactics.js` | 戦術一覧、カテゴリ、作図導線、保存、公開を置換 | `soccer-field`、`target-arrow`、戦術分類 |
| `drawing.js` | 作図ツールドックの操作アイコン、Undo/Redo、フレーム操作、保存・削除を置換 | 個別配置・図形・フレーム・保存のP40回帰 |
| `insights.js`・`utils.js` | インサイト、トースト、空状態、共通ボタンの置換 | 成功／注意／失敗とアイコンの意味整合 |

**P2の実装順:** `matches.js` → `practices.js` → `players.js` → `library.js` → `tactics.js` → `drawing.js` → 共通ユーティリティの順にします。各モジュールで、置換前後のスクリーンショット比較と関連契約テストを通してから次へ進みます。

## P3: 設定・同期・例外の置換とFont Awesome撤去

P3で依存を完全に切り替えます。移行期間の共存を終了する前に、設定・同期・エラー・保護者導線のような低頻度でも重要な画面を網羅します。

| 区分 | 具体的タスク | 完了条件 |
|---|---|---|
| 設定 | タブ、テーマエディタ、ワークスペース、マスター、データ管理のアイコンを置換 | 表示モード、テーマプレビュー、フォーム操作が維持される |
| 同期 | 送信・受信・再試行・成功・失敗・競合ダイアログを置換 | オフライン・送信中・成功・失敗の状態が判別できる |
| 共有・保護者 | 招待、コピー、期限、閲覧制限、写真・資料の導線を置換 | 保護者モードの権限制御が変わらない |
| 例外の処理 | アイコン名が一対一でない箇所をレビューし、意味優先でTabler名を確定する | 代替アイコンの理由を対応表へ記録する |
| 旧資産の撤去 | Font Awesome CDN、Service Workerの外部CDN扱い、`fa-*`クラス、不要な補助CSSを削除 | 実装上の`fa-`参照がゼロ、Font Awesomeへのネットワーク要求がゼロ |
| 回帰防止 | P42を強化して、`fa-solid`／`fa-regular`／`fa-brands`の再導入を禁止する | 全契約テスト、レスポンシブ、テーマ、PWA検証が成功する |

## P4: カスタムSVGの補完と運用定着

P4はTablerへの移行後に、CoachMgr固有の世界観を強化する継続改善です。Tablerを万能化せず、チーム固有の概念が必要な場面だけ既存のカスタムSVG体系を拡張します。

| 項目 | 具体的タスク | 期待効果 |
|---|---|---|
| SVG補完 | 設定、同期、データ保護など、主要導線に不足する固有アイコンがあるか監査する | サイドナビと主要導線の視覚言語を一段統一する |
| アイコン台帳 | 「意図 → 第一候補 → 代替候補 → 禁止」を一覧化する | 似た記号の重複利用を防ぐ |
| 変更レビュー | 新規UIのアイコン選定をPR／契約テストで確認する | Font Awesome再導入や直接SVG貼付けを防ぐ |
| サイズ最適化 | 実利用アイコンのWebfontサブセット化、または頻出アイコンのSVGマスク化を評価する | PWA初回キャッシュ容量を必要に応じて削減する |

## 共通品質ゲート

各フェーズの完了前に、以下を実施します。

| 観点 | 実施タスク |
|---|---|
| 構文 | `node --check`で変更したJSを確認する |
| 契約 | 全契約テストに加え、P38（ナビ）、P40（作図）、P41（ダッシュボード）、P42（Tabler）を実行する |
| レスポンシブ | 縦向き・横向きのスマホ、タブレット、デスクトップでアイコンの揃いとタップ領域を確認する |
| テーマ | 15色×ライト／ダークで、`currentColor`、状態色、ボタン内コントラストを検証する |
| アクセシビリティ | 単独アイコンの`aria-label`／`title`、装飾アイコンの`aria-hidden`、フォーカスリングを確認する |
| PWA | 初回取得、更新通知、オフライン再起動でローカルCSS・WOFF2を確認する |
| リリース | `version.js`、`sw.js`、キャッシュキー、更新履歴を更新し、GitHub ActionsとPagesを確認する |
