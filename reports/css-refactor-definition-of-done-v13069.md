# CoachMgr CSSリファクタリング完了の定義（Definition of Done）

**基準日:** v1.30.69（2026-08-20）  
**目的:** CSSリファクタリングを、単なる`!important`・`style`属性の件数削減ではなく、責務・可読性・保守性・画面回帰防止が担保された状態として完了させる。

## 1. 結論

現時点のv1.30.69では、**第一・第二段階で選定した高確度の対象範囲は完了**している。一方、CoachMgr全体のCSSリファクタリングを「完了」と判断するには、残る静的インライン装飾、通常装飾目的の`!important`、共有部品と画面固有規則の重複を、全件分類・正本化・検証する必要がある。

> 完了とは、`!important`とインラインスタイルがゼロになることではない。通常の見た目は正しいCSS層とセレクタで解決され、残る例外は動的値・状態・権限制御・Safe Area保護として説明可能で、回帰テストで守られている状態である。

## 3. 完了の必須受入基準

| 領域 | 完了条件 | 合格判定 |
|---|---|---|
| CSS責務 | 各共有`c-*`部品の正本が`components-standard.css`または`components-system.css`に一つだけある。画面固有CSSはページ固有修飾子のみを持つ | 重複セレクタ監査で、許可済みのレスポンシブ拡張以外の共有部品重複が0件 |
| `!important` | 全宣言が「状態」「権限制御」「アクセシビリティ」「Safe Areaを含むモバイル固定配置」「第三者・動的インライン保護」のいずれかに分類される | **通常装飾目的で未分類の`!important`が0件**。例外台帳にセレクタ・理由・所有者・テストがある |
| インラインスタイル | すべての`style=`が「動的値」「動的テーマ変数」「一時的状態」「静的」のいずれかに分類される | **静的レイアウト・静的装飾の未移行が0件**。残るインライン指定は動的理由を追跡できる |

| レガシー規則 | `u-ext-*`、旧画面固有クラス、未参照セレクタを全件棚卸しする | `audit-legacy-css.sh`で未参照規則0件。残存互換クラスには廃止予定または実行時用途が記録される |
| CSS層 | `base → tokens → layouts → components → components-standard → pages → components-system → utilities`の責務が崩れない | P33、P35のアーキテクチャ契約が成功し、正本の逆戻りがない |
| 視覚・操作品質 | 主要画面と状態の見た目・操作が保たれる | PC、768px、420px、ライト／ダーク、保護者／コーチ、テーマ15シードで確認。P38、レスポンシブ検証、手動視覚確認に成功 |

## 4. 完了までの残作業

### R1: インライン装飾の全件分類と静的値の移行

`index.html`、`app.js`、`matches.js`、`players.js`、`drawing.js`を対象に、`style=`を静的／動的へ分類する。モーダル、フォーム、一覧、ダッシュボード、試合詳細、作図パネルの固定幅・余白・Flex/Grid・色・フォントサイズは`c-*`または`l-*`へ移す。座標・進捗・テーマ・ドラッグ値だけを残す。

**完了条件:** 静的指定は共通部品またはページ固有修飾子に移行済みであり、残存する各動的スタイルに生成理由がある。

### R2: `base.css`の通常装飾と例外の完全分離

残る233件を、モバイルアプリシェル、状態、権限、通常装飾に分類する。トップバー、ボトムナビ、コンテキストバー、サイドバー、モバイルメニューを**一領域ずつ**扱う。通常装飾は正本部品へ移すが、Safe Area・固定位置・状態強制は例外台帳とP38で保護する。

**完了条件:** 未分類の通常装飾`!important`が0件。残る例外には必ずテストが結び付く。

### R3: ページCSSの共有責務を整理

`dashboard.css`（114件）、`components.css`（45件）、`drawing.css`（17件）について、共有`c-*`部品の重複を`components-system.css`へ統合する。ダッシュボード専用の配置、Canvas固有の動作、ページ専用の演出はページCSSに残す。

**完了条件:** 共有部品の正本が一つだけであり、ページCSSはそのページの固有責務だけを持つ。

### R4: レガシー台帳と契約テストの完成

残る`u-ext-*`の用途を、動的ランタイム用途、互換用途、削除候補に分類する。削除したものはP35で再導入禁止にし、保持したものは除去条件を記録する。

**完了条件:** レガシー監査0件、または許可済み残存の理由・廃止条件が台帳に記録済み。

### R5: 最終検証とリリース判定

各変更群に対して自動検証と視覚確認を実行する。1リリースでアプリシェル、権限制御、作図を同時に変更しない。全てのR1〜R4が終了し、最終監査の差分が説明可能であることを確認する。
