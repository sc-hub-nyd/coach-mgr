# CSSリファクタリング例外台帳（最終）

**対象バージョン:** v1.30.76 作業中
**目的:** 通常装飾の競合を`!important`で解決しないことを保証し、残る例外を機能保護の理由と検証手段とともに管理する。

## 1. 判定結果

`base.css`の実宣言を監査した結果、**通常装飾目的の`!important`は0件**である。残る宣言は、JavaScript状態、保護者モードの権限制御、モバイル固定アプリシェル、またはレスポンシブアプリシェルを保護する例外だけである。

| 分類 | 宣言数 | 保護対象 | 必須検証 |
|---|---:|---|---|
| Runtime state | 12 | `.hidden`、モーダル開放時、アクティブ状態、動的表示切替 | P35、P38、表示・非表示の手動確認 |
| Authorization | 4 | `body.role-read-only`配下のコーチ専用操作 | P20、P26、P38、保護者／コーチ切替 |
| Layout protection | 3 | 固定位置・重なり・ポインター操作を保つ宣言 | P38、対象画面の視覚確認 |
| Responsive app shell | 46 | トップバー、サイドバー、メイン領域の狭幅対応 | P38、768px／420px確認 |
| Mobile app shell | 98 | ボトムナビ、コンテキストバー、Safe Area、親指到達域 | P38、レスポンシブ20件、420px確認 |

## 2. 意図的に維持する例外

| 例外 | 維持理由 | 除去条件 |
|---|---|---|
| `.hidden`と`[style*="display: none"]` | JavaScriptが設定する表示状態を、コンポーネントの通常`display`規則より優先して隠すため | 表示状態が`hidden`属性または専用の`is-hidden`状態クラスへ全面移行し、全呼出元を検証したとき |
| `body.role-read-only` | 保護者モードで編集・削除・同期設定などの危険操作を確実に抑止するため | DOMを権限別に描画する構造へ変更し、操作要素自体を生成しないことを契約化したとき |
| `c-bottom-nav`・`c-context-bar`のモバイル固定配置 | Safe Area、固定位置、戻る導線、タップ領域を後続の汎用部品規則から保護するため | アプリシェル専用スタイル層を導入し、同等の優先順位をカスケード層で保証できるとき |
| モバイルのトップバー・サイドバー・本文上書き | 幅768px以下でPC規則を安全に打ち消すため | レスポンシブ専用カスケード層を導入し、PC規則と論理プロパティを完全分離したとき |

## 3. 運用規約

1. 新しい通常装飾で`!important`を追加してはならない。
2. 新規例外は、分類、対象セレクタ、理由、除去条件、契約テストをこの台帳へ追加してから導入する。
3. モバイルアプリシェルと権限制御の例外は、単独リリースまたは専用変更セットでのみ変更する。
4. P35・P38、レスポンシブ検証、保護者／コーチ、ライト／ダーク、テーマ15シードを通過しない例外変更は公開しない。

## 4. 監査成果物

詳細な行単位分類は`base-important-classification-v13076.tsv`、監査スクリプトは`scripts/audit-base-important.mjs`に保存する。1行に複数の`!important`宣言があるため、grepによる文字列数と行単位台帳の行数が一致しない場合がある。判定は宣言を持つセレクタ単位で行う。

## 5. 視覚受入

ローカル環境でダッシュボードと試合登録モーダルを確認した。共通静的スタイルカタログへの移行後も、PC幅のアプリシェル、カード、フォーム入力、スクロール、モーダル見出し、閉じる操作、フッター操作列に重なり・はみ出し・操作不能は確認されなかった。
